# CoGaze 実験 OPERATION BOOK — 実験の流れとデータ仕様

> 対象実装: 2026-07-04 時点の作業ツリー（最新コミット df94ea9 ＋ 被験者ID自動同期の修正）。
> 本書の焦点: **実験をどの流れで進めるか／どのタイミングでどのキーを押すか／どんなデータがどこに集まり、どうあるべきか**。
> 個々のトラブル対処の網羅は `OPERATOR_RUNBOOK.md` を参照（一部は本書時点の実装より古い記述を含む。差分は §5）。

---

## 1. 実験の全体構造

- **被験者内計画・10条件**: トラッキング {IR / Webcam / WebcamFiltered} × 可視化 {Ray / Circle / Frustum} の9条件 ＋ NoGaze（統制）。
- **提示順序**: PC起動画面で入力する「参加者インデックス (0–23)」から Williams 配置ラテン方格で決定。チェックリストに条件順プレビューが出るので、**毎回割付表と照合する**。
- **各条件の内部フロー**（`instructions_new.txt` テンプレートを10条件に展開）:

```
ConditionStart（視線キャリブ）
  → ノイズ 20s（自動） → 識別課題 60s → ノイズ 20s（自動）
  → 組立課題 180s → NASA-TLX（Worker回答）
```

- **3条件ごとに休憩**が自動挿入。全10条件終了後に **SSQ**（最終アンケート）。
- 役割: **Expert（PC）**＝進行の唯一の権威・視線の送り手（実験者が操作）。**Worker（Quest 3）**＝被験者。
- **被験者IDとインデックスはPC側で入力した値が自動的にQuestへ同期される**（roomプロパティ経由・参加時読み取り＋更新コールバック）。Quest側での入力は不要。Quest起動パネルにIDは表示されない（誤解防止のため撤去）— 代わりに「Photonサーバ接続」「Expertルーム検出（＝PC側が起動済みか）」のライブ状態が表示される。

## 2. 当日の流れ（時系列）

### Phase 1 — PC（Expert）起動【被験者到着前】

| 手順 | 操作 |
|---|---|
| 1 | PCアプリ起動 → 設定パネルで **参加者ID・参加者インデックス** を入力。条件順プレビューを割付表と照合 |
| 2 | 「Python を起動」→「起動済み ✓」を確認（未応答のままだと承認ボタンが有効化されない） |
| 3 | マイク選択 → テストバー「○ 入力検出中」を確認 |
| 4 | Fatal項目が消えたら **［開始］**（この時点でID/インデックスが部屋に公開される） |

**PC先行起動を推奨**: ID同期が最も確実な経路になり、Python/マイクの問題を被験者到着前に潰せる。

### Phase 2 — 被験者説明【装着前】

- 同意書 → 説明動画（外部再生。システム内に動画再生機能はない）。
- 口頭で伝えること: 「QR登録と選択は**右手グリップ**」「**休憩ではヘッドセットを外してよい。再開時は着け直してから声で合図**」「実験中に汗を拭く等で外す場合も声をかける（外すと課題タイマーは自動停止し、着け直すと自動再開する）」。

### Phase 3 — Quest（Worker）起動・セットアップ

| 手順 | 操作 |
|---|---|
| 1 | Questアプリ起動 → パネルの「✓ Photon サーバ: 接続OK」「✓ Expert ルーム: 検出」を確認して **Aボタン**（Expertルーム未検出でも開始は可能＝Worker先行順） |
| 2 | デュアルQRキャリブ: HUDの指示どおり赤枠QR-A→青枠QR-B を注視（読めない場合はコントローラを当てて右グリップのフォールバック） |
| 3 | タスクQR登録: 「A」から順にQRへコントローラを当てて右グリップ（成功で振動。無効な姿勢は自動拒否→再試行） |
| 4 | PC側は「Worker セットアップ」パネルで進捗（キャリブ／タスクQR n/n）を監視 |

### Phase 4 — 承認 → チュートリアル → 開始

| 状況 | Expertの操作 |
|---|---|
| 承認ボタンが緑（＝キャリブ完了＋QR全登録＋自側準備完了） | **Esc**（カーソル解除）→ **［承認して実験開始］** クリック |
| Tutorial 状態 | 音声疎通（会話）と映像（Worker視界がPCに映る）を確認 → **Enter** |
| Ready「準備完了」 | 被験者を開始位置へ移動させてから **Enter** → 3-2-1カウントダウンで条件1開始 |

### Phase 5 — 条件ループ中の操作（10条件 × 下表を反復）

| 状態（E画面の表示） | 押すもの | 備考 |
|---|---|---|
| **ConditionStart**（IR / NoGaze条件） | **Enter** | キャリブ不要 |
| **ConditionStart**（Webcam系条件） | キャリブ自動実行→ **PASS: Enter** / **MARGINAL: Enter**（許容続行） / **FAIL: R**（再試行） | キャリブ中はEnter無効。90秒無応答でタイムアウト表示→［R］再試行/［Enter］スキップ |
| **ノイズ 20s** | 何も押さない（自動終了） | |
| **インターバル終了（NoiseComplete）** | **Enter** | |
| **識別課題 60s** | **F2 / F3**（発話の段を上げた瞬間） | Workerの正グリップで**自動前進**、または満了。F4は無効 |
| **組立課題 180s** | **F2 / F3 / F4**（F4=向きの指示） | 満了で自動前進。早期終了は **Del 0.8秒長押し** |
| **タスク完了（TaskComplete）** | **Enter** | |
| **NASA-TLX（アンケート中）** | **何も押さない** | Worker提出で自動前進。Enterは提出前は無効化済み。Workerフリーズ時のみDel長押し（欠測扱い） |
| **休憩（3条件ごと）** | 被験者: 外して休憩→着け直して声で合図 → Expert: **Enter** | |
| **課題中にWorkerがHMDを外した** | **何も押さない** | 「⚠ Worker の HMD が外されました」表示・タイマー自動停止→装着で自動再開 |
| **Finished ＋ SSQ** | **何も押さない** | Worker のSSQ提出までExpert側終了画面は保留される。「最後のアンケートまで外さないで」と伝える。緊急時のみDel長押しで解除 |

### 発話エスカレーション（実験の主要測定・押し忘れ厳禁）

段1（指示語＋視線「これ・そこ」）から開始し、**約10秒通じなければ**次の段へ。**段を上げて発話するその瞬間にキーを押す**。

| 段 | 発話 | キー |
|---|---|---|
| 1 | 指示語のみ「これを・そこに」 | なし（既定） |
| 2 | 特徴・相対語「赤いQR／ひとつ右のマス」 | **F2** |
| 3 | 空間・座標語「右上のQR／中央手前」 | **F3** |
| 4 | 向き「90度右に回して」（**組立のみ**） | **F4** |

- 押し忘れ＝max_rung過小（下振れ）。押し間違い＝過大（上振れ・下げられない）。間違えたらその場でメモ。
- NoGaze条件も同じキーで記録（高い段に達するのが想定どおり）。

### Phase 6 — 終了・次の被験者

1. SSQ提出を確認 → アプリ終了。
2. §3のチェックリストでデータを確認・回収。
3. 次の被験者: **PCアプリを再起動してIDとインデックスを変更**。Questは再起動のみ（新しい値に自動追従）。

## 3. 収集データ — 何が・どこに・どうあるべきか

### 3.1 保存場所

**PC（Expert）側** — `%USERPROFILE%\AppData\LocalLow\<会社名>\CoGaze\`:

```
logs\{参加者ID}\
├── voice_local_{起動時刻}_sNN.wav    ← Expertマイク（条件ごとに1本、NASA-TLX時に書き出し）
├── voice_remote_{起動時刻}_sNN.wav   ← Worker側音声（受信音声）
└── P{参加者インデックス}\
    ├── trials.csv           ← 試行メタ（1試行1行）
    ├── frames.csv           ← 30Hz 時系列（視線・両者頭部・コントローラ）
    ├── escalations.csv      ← F2-F4押下イベント
    ├── identifications.csv  ← 識別課題のグリップ試行ごとの正誤
    └── replay_{trialId}.json ← 試行ごとのリプレイデータ（20個）
```

- 実行ログ: `<exeのあるフォルダ>\cogaze_{日時}.log`
- アンケートPCコピー: `<exeのあるフォルダ>\questionnaire_{参加者ID}.json`（Workerが提出するたびRPCで上書き転送される全量コピー）

**Quest（Worker）側** — `Android/data/<パッケージ名>/files/`:

- `questionnaire_{参加者ID}_{日時}.json` ← **アンケート原本**（NASA-TLX×10＋SSQを蓄積、アトミック書き込み＋.bak）
- `logs\{参加者ID}\voice_*.wav`、`cogaze_{日時}.log`

**Python（視線トラッキング）側** — WebcamEyeTracking リポジトリの出力先。条件開始ごとに `session_start(参加者ID, 条件名)` が通知されるので、セッションが参加者ID・条件名で紐づく。

### 3.2 主要ファイルの中身

**trials.csv（1試行=1行、分析の起点）**

| 列 | 意味 |
|---|---|
| trial_id | 試行の一意ID（全ファイル・replay JSONとの結合キー） |
| participant | 参加者ID |
| condition_index / gaze_mode / noise_level / condition_name | 条件（例: circle / webcamfiltered） |
| task_type / step_type / step_index | task（識別）or assembly（組立） |
| start_ms / end_ms / duration_ms | Unixミリ秒と所要時間 |
| identified_marker / target_marker / **correct** | Worker選択QR・正解QR・**自動採点(1/0)**。組立行は空欄 |
| **max_rung** | 到達した発話エスカレーション最高段（1–4） |
| score | 識別課題スコア |
| calib_quality / calib_err_x / calib_err_y | 直近の視線キャリブ結果（webcam系条件のみ値が入る） |

**frames.csv（30Hz）**: trial_id, t_ms, elapsed_s, 視線x/y/blink, Worker頭部姿勢(7), Expert頭部姿勢(7), osc_certainty, Workerコントローラ位置(3)。

**escalations.csv**: trial_id, t_ms, elapsed_s, condition_index, task_type, rung — 何秒時点で段が上がったかの時系列。

**identifications.csv**: 識別課題中の全グリップ試行（target_id, gripped_id, correct, score_after）— 初正解までの時間・試行回数の分析用。

**questionnaire JSON**: NASA-TLX（条件ごと6項目）×10 ＋ SSQ。participant_id フィールドで照合。

### 3.3 セッション直後のサニティチェック（あるべき姿）

被験者を帰す前に1分で確認する:

| # | チェック | あるべき値 |
|---|---|---|
| 1 | `logs\{当日のID}\P{当日のインデックス}\` が存在 | フォルダ名が当日の入力値と一致 |
| 2 | trials.csv の行数 | **20行**（識別10＋組立10）＋ヘッダ。少ない＝中断あり |
| 3 | trials.csv の participant 列 | 全行が当日のID（P00が混ざっていたら同期失敗） |
| 4 | 識別(task)行の correct | 全行 0/1 が入っている（空欄＝targets設定漏れ） |
| 5 | **max_rung の分布** | **全行1なら F2-F4 の押し忘れを疑う**（特にNoGaze条件が1は不自然） |
| 6 | webcam系条件行の calib_quality | 値が入っている（空欄＝キャリブスキップ、ノートと突合） |
| 7 | frames.csv | 識別≈1,800行/試行・組立≈5,400行/試行のオーダー |
| 8 | replay_*.json | 20個 |
| 9 | WAV | voice_local / voice_remote が条件数ぶんペアで存在 |
| 10 | Quest側 questionnaire JSON | NASA-TLX 10件＋SSQ 1件、participant_id一致（PCコピーでも代用可） |

### 3.4 追記仕様と再走の扱い

- 同一ID・同一インデックスで再起動すると**CSVは追記**される（上書きされない）。起動画面に「logs/{ID} が既に存在」警告が出る。
- 試行は trial_id（GUID）で区別できるため追記自体は壊れないが、**中断→取り直しをした場合はどの trial_id を採用するかを実験ノートに残す**こと（解析時に start_ms でも判別可能）。

## 4. 実験の妥当性を守るためにExpertが「してはいけないこと」

| 禁止 | 理由 |
|---|---|
| NASA-TLX中に急かして進めようとする | Enterは無効化済みだが、Del長押しは欠測を生む |
| タスク中に **M**（メッシュ表示）/ **WASD・マウス**（フリールック） | 被験者の気を散らす／共有視線の原点がずれてデータ汚染 |
| ConditionStart中に **1/2/3**（可視化モード手動変更） | 次タスクに誤モードが持ち越され条件が汚染される（タスク中はロック済み、境界では無防備） |
| 段を上げてからまとめてF2-F4を押す | escalations.csv のタイムスタンプが実態とずれる。**押してから喋る** |
| SSQ提出前に「終わりました」と伝える | 被験者がHMDを外すとSSQ欠測（Expert画面は提出まで保留される仕様を信頼する） |

## 5. 旧 OPERATOR_RUNBOOK.md からの主な変更点（本書時点で解消済み）

| 旧記述 | 現状 |
|---|---|
| Delは即時発火・誤爆でデータ破壊 | **0.8秒長押し**に変更済み |
| Questionnaire中のEnter早押しでTLX欠測 | 提出前Enterは**無効化済み**（StepTypeでゲート） |
| session_start ACK待ちで無期限デッドロック | **90秒タイムアウト**＋［R］/［Enter］復帰導線を実装済み |
| HMD一時取り外しで無自覚な切断連鎖 | **OnApplicationPause実装済み**: タイマー自動停止・Expertに警告表示・再装着で自動再同期 |
| SSQの提出忘れ | **SSQゲート実装済み**: 提出までExpertのFinished画面を保留 |
| 再接続後にWebRTC映像/音声が復旧しない | 切断時にガードをリセットし**再入室で自動再確立**するよう修正済み |
| WorkerのIDが常にP00 | **Expertの値を自動同期**（参加時読み取り＋roomプロパティ、Quest設定にも永続化） |
| 起動時セルフチェックが無い | StartupUI/Workerパネルに**チェックリスト実装済み**（Fatalで開始ブロック） |

旧ランブックの §1-A（Setupのトラブル）、§1-X（切断・再接続）の対処表は引き続き有効。
